## الگوی Use Case (نمونه UC-02)

**UC-02: رزرو نوبت**
- **Actor:** بیمار (انونیم → Authenticated)
- **Precondition:** Slot آزاد در بازه قابل رزرو وجود دارد.
- **Main Flow:**
  1. بیمار صفحه «دریافت نوبت» را باز می‌کند.
  2. تقویم + Slotهای آزاد (Jalali) نمایش داده می‌شود.
  3. بیمار روز و ساعت را انتخاب می‌کند → Server یک **Hold** (TTL 10 دقیقه) ثبت می‌کند.
  4. سیستم درخواست Login می‌کند → بیمار شماره موبایل وارد می‌کند.
  5. OTP ارسال می‌شود (SMS)؛ بیمار کد را تأیید می‌کند.
  6. بیمار جدید: تکمیل پروفایل / بیمار قبلی: انتخاب Patient مرتبط.
  7. Server آزاد بودن Slot را **دوباره** بررسی می‌کند → Appointment `confirmed` ساخته می‌کند (Hold→Claim) + کد نوبت.
  8. اعلان تأیید (SMS/Internal) Queue می‌شود.
- **Alternative Flows:**
  - 3a: Slot توسط دیگری رزرو شد → `CLINIC_SLOT_TAKEN` + پیشنهادهای جایگزین.
  - 5a: OTP نادرست (≤5) → تلاش مجدد؛ 5 اشتباه → قفل 15 دقیقه.
  - 7a: Hold منقضی شده → «زمان رزرو تمام شد» + شروع مجدد.
- **Postcondition:** یک Appointment `confirmed` + آزادسازی Hold + Audit + اعلان.
- **Non-functional:** بدون Double-Booking (NFR-CONC-1)، بدون Block روی نوبت‌دهی (NFR-PERF-5).

> بقیه Use Caseها با همین الگو در فاز پیاده‌سازی تکمیل می‌شوند (مراجع SRS در ستون بالا).

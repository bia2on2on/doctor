## 1. درس‌آموخته (Incident)

## 2. قواعد دائمی (از این لحظه الزام‌آور — حتی قبل از تأیید Precedence)

1. **STOP:** با یافتن تعارض بین هر دو مورد از {تصمیم نهایی کارفرما، ADR، Baseline، SRS، State Machines، ERD، API Contract، Settings، Implementation} — **هیچ Fix خودسرانه‌ای اعمال نشود.**
2. **Report:** محل دقیق + نقل‌قول هر دو طرف تعارض (کد سطر/بند).
3. **Impact Analysis:** کوتاه — Security / Performance / Data / Scope.
4. **Wait:** منتظر تصمیم کارفرما — **مگر** تعارض با Precedence تأییدشده §3 کاملاً مشخص حل شود؛ در آن حالت: اعمال + **ثبت در Report فاز + Decision Log** (Traceability).
5. **هیچ Fix «چند سطر هم» استثناء نیست** اگر سند-به-سند Conflict Resolve کند.
6. **تصمیم نهایی کارفرما بر همه برتری دارد** (شامل این Policy).

## 3. Precedence پیشنهادی (برای Resolve خودکار تعارض — نیازمند تأیید)

| اولویت | سند | قلمرو |
|---|---|---|
| 1 | **تصمیمات نهایی کارفرما** (Decision Log / بخش «تأیید نهایی» ADRها) | همه |
| 2 | **ADRهای تأییدشده** (وضعیت: تأیید نهایی) | فقط Scope همان ADR |
| 3 | **Engineering Baseline v1.0** | الزامات دائمی (امنیت/عملیات/کیفیت) |
| 4 | **SRS** | نیازمندی‌های کارکردی |
| 5 | **State Machines + ERD** | مدل‌های طراحی (رفتاری/داده‌ای) |
| 6 | **API Contract** | قرارداد Interface |
| 7 | **Settings (Defaultها)** | Config زمان‌اجرا — باید از سندهای ۳–۶ مشتق باشد |
| 8 | **Implementation** | کد — حق انتخاب Source ندارد |

**تفسیرها:**
- Settings ↔ SRS: SRS برنده (Settings مشتق است) — **اما** تعارض باید Report شود (تعارض نشانه Defect در سند بالاتر هم هست).
- ADR ↔ SRS (در Scope ADR): ADR برنده (ADR = تصمیم جدیدتر و تأییدشده).
- **تناظر هم‌رتبه** (مثلاً SRS ↔ ERD یا SM ↔ Contract): Precedence Resolve **نمی‌کند** → Report + Wait.
- Precedence فقط می‌گوید «کدام گزاره برنده است» — **ثبت Conflict در Report/Log در هر صورت اجباری است.**
